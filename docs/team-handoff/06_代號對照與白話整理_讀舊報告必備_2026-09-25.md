## 1. 整個系統在做什麼（白話）

| 步驟 | 做什麼 | 對應名詞 |
|---|---|---|
| 0 | 每張切片先被切成幾千個小圖塊（patch），每個 patch 用凍結的 CONCH 變成一個 512 維向量。這一步是現成的，我們不訓練 | patch、CONCH 特徵 |
| 1 | 拿到一張新切片，先判斷它屬於哪個任務（食道、腎、乳房、肺） | router、任務辨識（TP） |
| 2 | 交給那個任務的 expert。expert 是一個小網路，負責從幾千個 patch 裡挑出最有診斷價值的 64 個 | expert（以前叫 NavRouter、MicroRouter） |
| 3 | 把挑出來的 64 個 patch 平均，和該任務兩個類別的文字描述比相似度，較像的那一類就是答案 | 凍結的 CONCH 文字頭 |

這就是 MoE（mixture of experts）的結構：每個任務一個 expert，router 決定交給哪一個。LoRA 用在 expert 上：expert 共用一個底座，每個任務只多學一小塊修正量。

## 2. 任務與評估指標

| 代號 | 白話 |
|---|---|
| 任務 | 四個癌種的二分類：ESCA（食道：腺癌 vs 鱗癌）、RCC（腎：透明細胞 vs 乳突）、BRCA（乳房：乳管 vs 小葉）、Lung（肺：腺癌 vs 鱗癌）。注意食道和肺的兩個類別是同一對組織型 |
| TIL（task-incremental） | 測試時告訴模型這張片子是哪個任務，只要在該任務的 2 類裡選。benchmark 裡叫 Masked ACC |
| CIL（class-incremental） | 測試時不告訴任務，要在 8 類裡選。benchmark 裡叫 ACC，QPMIL-VL 的 0.859／0.890 就是這個 |
| WP | 任務內正確率 = 已知任務時的正確率 = TIL |
| TP | 任務辨識正確率：router 把片子派到正確任務的比例 |
| TP × WP | 老師的乘法：CIL 大約等於 TP 乘上 WP。我們實測誤差不到 0.003 |
| oracle | 「作弊版」：直接告訴系統正確答案（例如正確任務），用來量上限 |
| Forgetting | 學了後面的任務之後，前面任務的正確率掉了多少（每個任務歷史最高減最後，再平均） |
| BWT | 每個任務「最後」減「剛學完」的平均。我們的系統裡剛好等於 −Forgetting |
| Masked ACC | 只在真實任務的 2 類裡比的正確率；證據來自 router 分派到的 expert |
| 十折 | 資料切成 10 種訓練／測試組合，各跑一次再平均，數字才穩 |
| reverse／paper（forward）順序 | 任務學習的先後順序。reverse：食道→腎→乳房→肺；paper（forward）：肺→乳房→腎→食道 |
| validation／test | validation 用來選設定；test 只用來報最後的數字，不能拿來選 |
| macro／micro | macro：四個任務的正確率先各自算、再平均（每個任務權重一樣）；micro：所有片子混在一起算（片子多的任務權重大） |
| margin | router 對第一名和第二名任務的分數差，差越小代表越沒把握 |
| pp | 百分點。0.8900 → 0.8987 是 +0.87 pp |
| 贏折數（如 7/10） | 十折裡，新方法比基準高的有幾折。我們的門檻通常是至少 7 折 |
| paired | 同一折、同一批片子上兩個方法直接相減，比兩個平均數相減公平 |
| CI（信賴區間） | 差值可能落在的範圍。區間跨過 0，就不能說有差 |
| t = 2、3、4 | 已經學到第幾個任務。t = 4 是四個任務都學完 |

## 3. 選 patch（expert）相關

| 代號 | 白話 |
|---|---|
| K = 64 | 每張片子最多看 64 個 patch（觀察預算） |
| top-k | 依某個分數挑分數最高的 k 個 patch |
| 四輪 | 64 個 patch 分四輪、每輪挑 16 個；第二輪起，和已選 patch 太像的會被扣分，避免重複 |
| one-shot | 一次挑完、不分輪 |
| λ（lambda）、λ\* | 四輪選片裡「太像就扣分」的強度；λ\* 是選定的值 1.5 |
| **top-8，意思一：one-shot top-8**（全局計畫文件 2.3 節那一列） | **已訓練的 expert** 一次挑分數最高的 8 個 patch 來判讀。fold 1、reverse、router 用正確答案、8 類輸出，四任務平均 0.8797。出處 pathselect 的 Exp0 預算掃描（K 從 1 到 64，K = 8 最好） |
| **top-8，意思二：zero-shot top-8**（PathSelect 論文用語） | **不訓練**，每個 patch 和 8 個類別文字算相似度，挑最像的 8 個，等權平均後判讀。十折 ACC 0.812 ± 0.024、Masked ACC 0.899 ± 0.019。是 learned selector 必須贏過的「零參數基準」 |
| zero-shot top-64 | 同意思二，但挑 64 個，也不訓練。第一關的對照 (b)，TIL 0.9005 |
| 第一關 (a)–(e) | (a) 全部 patch 平均；(b) zero-shot top-64；(c) 隨機挑 64 個；(d) expert 一次挑 64 個；(e) expert 四輪挑 64 個 |
| expert | 每任務一個選 patch 的小網路（2 層，約 13 萬參數），以前叫 NavRouter、MicroRouter、TextNavRouter、EvidenceSelector；程式裡叫 selector |
| bank | 存放所有任務 expert 權重的檔案 |
| v9 | navipath 時期訓練好的那一組 expert 權重（第 9 版），pathselect 拿來純推論用 |
| DELTA_v9 | pathselect 8/21 的報告：把 v9 的分類頭換成乾淨的 CONCH 頭重測，0.8738 |
| Exp0 | pathselect 的實驗 0：選片預算 K 從 1 到 64 的掃描（隨機、等距、zero-shot、已訓練 expert 四條線） |
| S1 | pathselect 的任務可分性診斷：slide 平均特徵做 4 類線性分類，0.9821（四任務資料一起訓練，只當上限） |

## 4. LoRA 相關

| 代號 | 白話 |
|---|---|
| LoRA | 不重新訓練整個網路，只在原本的權重上加一個「低秩修正量」。修正量很小，每個任務各存一份 |
| BA | LoRA 修正量的寫法：兩個小矩陣 B 和 A 相乘。B 一開始設 0，所以一開始等於沒修正 |
| 底座（base） | 共用的 expert。我們用「第一個任務的完整 expert」當底座，凍結不動 |
| **r（rank）** | LoRA 修正量的大小，可以想成「這個任務能用幾個方向去調整底座」。r 越大，能調的越多，參數也越多 |
| r 對應的參數量 | 每任務 770r + 513：r = 1：1,283；r = 2：2,053；r = 4：3,593；r = 8：6,673（完整 expert 是 132,097） |
| **r\*** | 我們事先訂的規則：「正確率不比完整 expert 低超過 0.01 的最小 r」。結果 r\* = 2，也就是每個任務只要 2,053 個參數（完整 expert 的 1.6%） |
| L0 | 每個任務一個完整 expert（不用 LoRA） |
| L1(r) | 共用底座＋每任務 rank r 的 LoRA |
| L2 | 把所有任務的 LoRA 加起來合併成一個 expert、不用 router。結果只有 0.64–0.71，所以 router 是必要的 |
| 0z、0b | NC-4 的兩個「0 參數」選項：0z = 不用 expert，直接用 zero-shot 選片；0b = 直接沿用底座 expert |
| I6（VLM 先驗低秩 expert） | expert 分數 = zero-shot 分數＋每任務一個很小的修正（r = 2，1,033 參數）；不依賴第一個任務。NC-7 通過，現在的主系統用它。**10/8 的匯報裡叫「修正頭」** |
| D1、D2、D3 | AR＋LoRA r=2；AR＋完整 expert；AR＋I6（主系統） |
| 轉交 | router 沒把握的片子交給病理醫師；轉交 5% 接住 85% 的分派錯誤 |
| I7（容量依需求） | 每個新任務用自己的 validation 在 {0z、0b、r = 1、2、4、8} 裡挑最省的；NC-4 沒過（test WP 掉 0.006） |
| NaN | 數值運算出錯（不是數字）。r = 1 時出現，已修正 |
| AMENDMENT-1 | 修 NaN 的紀錄文件：寫明問題、修法、影響範圍 |
| v1／v2 | LoRA 那張表的第一版與修正後重跑的第二版 |
| Jaccard | 兩組挑出來的 patch 重疊多少（0 = 完全不同，1 = 完全一樣）。LoRA 與完整 expert 只有 0.10–0.29，正確率卻一樣 |
| Pearson | 兩組分數的相關係數 |
| Frobenius norm | 一個矩陣「有多大」的量法，這裡用來量 LoRA 修正量有多大 |

## 5. Router 相關

| 代號 | 白話 | 要存什麼 | CIL |
|---|---|---|---|
| router | 判斷片子屬於哪個任務、該交給哪個 expert。MoE 文獻裡叫 gate | — | — |
| Hard | router 選一個任務，只在該任務的 2 類裡判 | — | — |
| Hard-8 | router 選一個任務的 expert 挑 patch，但在 8 類裡判 | — | — |
| Soft | 依 router 的機率把各 expert 的答案加權；結果和 Hard 幾乎一樣 | — | — |
| text-class | 整張片子平均向量，和所有已見類別的文字比，最像的類別屬於哪個任務就派過去 | 不存 | 0.8142 |
| **R0（T-Hard 規則）** | 同上，但比的是「每個任務兩個類別文字的平均」，是同學 T-Hard 的規則 | 不存 | 0.8617 |
| text-organ | 用器官名稱的文字（esophagus、lung…）來比 | 不存 | 0.6956（TP 0.71） |

| **R3（k = 8）** | 每個任務存 8 個平均向量（用 k-means 分群），看最像哪個。**9/25 當時採用** | 16 KB／任務 | **0.8987** |
| k | R3 每個任務存幾個平均向量 | — | — |
| KMeans（k-means） | 把一堆向量分成 k 群，每群取中心 | — | — |
| R4 | R2 與 R1 分數相加 | 2 KB | 0.8686 |
| nav、R5 | 用 expert 挑出來的 patch 判斷任務 | 0～2 KB | 0.77、0.82 |
| R6（codebook 投票） | 每任務從訓練 patch 分出 8 個代表向量（codebook，每個叫 codeword）；測試時每個 patch 投給最像的任務 | 16 KB | 0.8905 |
| R7（patch 對角高斯） | 每任務存 patch 特徵每一維的平均與變異數；每個 patch 投給距離（Mahalanobis）最近的任務 | 4 KB | 0.8808 |
| R8 | router 沒把握時，讓前兩名的 expert 都看，再比較（MoE 的 top-2 分派） | 不額外存 | 和 R3 相同，沒有幫助 |
| E-max | 不分派，把所有 expert 的 patch 分數取最大值來挑 patch | 不存 | 0.6918 |
| B1（I5，NC-4） | 新任務的訓練片子若被現有 key 分錯，就只在分錯的地方加 key | ≤ 16 KB | 0.8759／0.8909（沒贏） |
| B2（I4，NC-4） | 用舊任務的平均與變異數抽「假特徵」，和新任務一起訓練一個線性 router | 12 KB | 0.8966／0.8979（沒贏） |
| key | router 存下來拿來比對的向量（平均向量、codeword 等） | — | — |
| 背景分派（ctx，NC-5） | router 只看「不像腫瘤」的 patch 的平均，expert 照舊看腫瘤 | 16 KB | 沒過；最好 0.8998 |
| 解析式 router（AR，NC-5） | Any-SSR 那種 router：依所有訓練片子的共變異重新加權後做線性判斷，用封閉解一次算出；累加統計量就能更新，不會忘。**9/25 起為主 router；10/8 匯報裡叫「閉式 ridge 分派器」** | 約 1 MB 共用（fp32） | **0.9171**（L0 expert） |
| 8 類線性基線（LIN8，NC-5） | 不用 expert、不用文字頭，直接在 slide 平均向量上用同樣的封閉解做 8 類分類 | 約 1 MB 共用 | 0.8566 |
| AR-bal（NC-6） | AR 加上依任務樣本數加權，避免食道這種小任務被壓過 | 同 AR | 0.904–0.921，validation 沒選到 |
| TSP（NC-6） | 文字引導的組織型方向移除：用類別文字找出組織型方向，從特徵拿掉再分派 | 不額外存 | 沒過（R3＋TSP 0.890） |
| 白化後的 R2（NC-6 機制檢查） | 先依所有訓練片子的統計量重新加權，再做 R2 | 同 AR | 0.905 |
