## 1. 空間在哪裡

| 項目 | 數字 | 意思 |
|---|---|---|
| 主系統 CIL ACC（ridge TP＋residual scoring head） | 0.9128（兩序相同） | 不告訴任務 |
| 告訴任務（oracle TP，同一批 head） | 0.9340 | TP 全對時的上限 |
| 告訴任務＋全參數 head | 0.9399 | head 放大 128 倍，只多 0.6 pp |
| TP 正確率 | 0.986 | 聯合訓練的線性分類（非 CL）是 0.982，已在同一水準 |
| 8 類 ridge（不拆 TP／WP） | ACC 0.8566，Masked ACC 0.9243 | 只看整片平均向量，在任務內分兩類也有 0.924 |
| Zero-shot | ACC 0.8270，Masked ACC 0.9044 | 不訓練 |

| 來源 | 目前錯多少 | 最多能補回 | 已經試過的 |
|---|---|---|---|
| TP 判錯任務 | 1.4% 的 slide | 2.1 pp | 12 種 router 改法都沒贏；剩下的錯誤集中在肺鱗癌與食道鱗癌 |
| WP 判錯亞型 | 6.6% 的 slide | 未知；全參數 head 只多 0.6 pp，代表「把同一種 head 放大」沒用，要換資訊來源 | top-K、輪次、容量依需求 |

還沒試過的那一格（2 × 2）：

| | 判器官（TP） | 判亞型（WP） |
|---|---|---|
| 整片統計（所有 patch 的平均向量） | 現在的 ridge TP，0.986 | 8 類 ridge 的 Masked ACC 0.924；沒有和局部證據合起來用過 |
| 局部證據（挑出的 64 個 patch） | 試過三次都失敗 | 現在的 residual scoring head，0.934 |

右上那一格是 M3 的出發點。（事後證明：真正有效的不是把兩種 expert 相加，而是把讀出改成閉式 ridge——這條線在 MOE-2 到 MOE-4 走出來。）

## 5. 文獻現況：哪些已經有人做了

| 論文 | 做了什麼 | 對我們的意思 |
|---|---|---|
| Any-SSR（ICCV 2025） | closed-form 分派到每任務 LoRA，不 replay | 我們目前的骨架 |
| MoE-Adapters4CL（CVPR 2024） | CLIP 內的 MoE adapter | 「舊 expert 凍結、新任務沿用」已有前例 |
| MoTE（arXiv 2506.11038） | 每任務一個 adapter；對任務不明確的樣本做加權混合 | M1 的想法已有前例 |
| TUNA（ICCV 2025） | 每任務 adapter＋一個通用 adapter | 「專屬＋通用」已有前例 |
| SAEF（arXiv 2602.20911） | 依語意把任務分群，群內合併 adapter | M2 最接近的前例 |
| CaRE／BR-MoE（arXiv 2602.03473） | 兩層 routing | 階層式 routing 已有前例 |
| StaR-MoE（arXiv 2605.17571） | 新增 expert 會讓舊類別的 routing 漂移 | 我們的 gate 是 closed-form、head 凍結，沒有這個問題 |
| PAMoE（CVPR 2025）、Mixture of Mini Experts（ICLR 2026）、ROAM | WSI 的 MoE，把 patch 或 region 分給不同 expert；都不是 CL | 不往這裡走 |
| MergeSlide（WACV 2026）、COSFormer、QPMIL-VL | WSI 的 CL | 目前沒看到「WSI 的 CL＋MoE 混合」 |

## 6. 三個設計

### 6.1 M1：任務層級的 soft gating（MoE 基準列）

| 項目 | 內容 |
|---|---|
| 機制 | gate 給四個任務各一個權重 π；四個 head 都跑；類別 c 的分數 = π[c 所屬任務] × 該任務 head 對 c 的機率 |
| 訓練 | 不需要；π 由既有 ridge 分數經 softmax 得到，只多一個 temperature |
| 預期 | 與 hard routing 幾乎相同（TP 98.6% 對，π 接近 one-hot） |

### 6.2 M2：跨器官共用 expert，gate 由類別文字決定

| 項目 | 內容 |
|---|---|
| 觀察 | 食道與肺的兩類是同一對組織型（腺癌／鱗癌）。兩個 head 學的可能是同一件事 |
| 機制 | 每個 expert 有一把 key：該任務兩個亞型文字向量的差。新任務來時，算它的 key 和每個舊 expert 的 key 有多像；夠像的舊 expert 直接沿用 |
| 先決條件 | B2：肺的 head 用在食道（以及反過來）的正確率，不低於自己的 head 1 pp 以上 |

### 6.3 M3：整片統計 expert 與局部證據 expert 的混合

| 項目 | 內容 |
|---|---|
| 觀察 | 只看整片平均向量的 ridge，在任務內分兩類有 0.924；挑 64 個 patch 的 head 有 0.934。兩者用的資訊不同 |
| 機制 | 每個任務有兩個 expert：局部證據 expert（residual scoring head）與整片統計 expert（closed-form ridge）。gate 決定兩者各佔多少 |
| gate 的兩個版本 | (a) 固定權重 λ；(b) 依兩個 expert 各自的把握程度決定權重 |
| 先決條件 | B3：「至少一個對」比主系統 WP 高 2 pp 以上；B4：validation 上簡單融合比主系統高 0.5 pp 以上 |

### 6.4 建議

| 順位 | 設計 | 理由 |
|---|---|---|
| 主線 | M3 | 對準目前最大的錯誤來源（WP 的 6.6%）；不 replay 的理由最單純；診斷便宜 |
| 第二 | M2 | 四個任務只有一對可共用，單獨撐不起 |
| 基準 | M1 | 一定要有的一列，不當創新 |

## 8. 這一輪不做的

| 項目 | 原因 |
|---|---|
| 在 TP 端做 MoE | 已有 12 個負結果；TP 0.986 已在聯合訓練線性分類的水準 |
| 把每個 patch 分給不同 expert | 與 PAMoE 等重疊，且與任務層級的 CL 無關 |
| 在 image encoder 內做 LoRA-MoE | 特徵是預先抽好的，要從原圖重抽 |
| gate 穩定化 | 我們的 gate 是 closed-form、head 學完凍結，沒有 gate 漂移 |

## 9. 本頁代號

| 代號 | 意思 |
|---|---|
| ridge TP | 用最小平方法 closed-form 解出的任務分類器；只存累加統計量（程式代號 AR） |
| 8 類 ridge | 同樣的 closed-form，直接分 8 類（程式代號 LIN8） |
| residual scoring head | 每任務一個的小網路（1,033 參數），在 zero-shot 分數上加修正量（程式代號 I6；10/8 匯報叫「修正頭」） |
| hard routing／soft gating | 只選一個任務的 head／給每個任務一個權重 |
| M1、M2、M3 | soft gating 基準；跨器官共用 expert；整片統計與局部證據兩種 expert 的混合 |
| G-M3、G-M2 | 決定要不要實作 M3、M2 的判讀門檻 |
