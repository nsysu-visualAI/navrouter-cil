# NavRouter 延伸成 CIL：老師新佈局的全局與兩週計畫（2026-09-24，節錄）

節錄說明（2026-10-08）：原文件含機器設定（MSI／Mac）、時程與七次修改對照；這裡只保留與設計、判準、文獻定位有關的部分。「PI」在文件裡指 Aaron（做決定的人），不是老師。

名稱：期中報告圖中稱 NavRouter、表中稱 NaviRouter，docx 稱 MicroRouter，程式是 navipath `zeronav/` 的 TextNavRouter，在 pathselect 改名為 EvidenceSelector。本頁統一稱 **NavRouter**。

---

## 結論

| # | 問題 | 結論 |
|---|---|---|
| 1 | 老師的構想站得住嗎 | 站得住。「0.93 × 0.92 ≈ 0.85」就是 Kim et al.（NeurIPS 2022）的分解：好的任務內預測（WP）與好的任務辨識（TP）是好的 CIL 的充分必要條件。先把 WP、TP 分開做好再組合，每一關只加一個變數，這個順序是對的 |
| 2 | 0.93 能直接拿來乘嗎 | 不能。期中報告表一、表二來自 navipath 7/2 與 7/31 的 run：router 的輸入在 7/2（ZeroNav）已經拿掉 QPMIL 的 prototype，但類別文字特徵與推論的分類器仍是 QPMIL-VL 學完四任務的 checkpoint。8/20 起 pathselect 全面改用乾淨的 CONCH 文字頭，8/21 用同一組 router 重測：one-shot top-64 由 0.9030 降到 0.8738（等權聚合 0.8878）。往上乘的基數應該是 0.87–0.89 |
| 3 | T-Hard 是新東西嗎 | 不是。「slide 表徵對任務層級 prompt 算相似度，先判任務再判類別」就是 MergeSlide（WACV 2026）的 task-to-class prompt-aligned inference；每任務專家的做法 COSFormer（MedIA 2026）也有；用專家自己的 entropy 選 adapter 是 TUNA（ICCV 2025）。第一到三關做出來的是**強基線**，不是貢獻 |
| 4 | 新穎性從哪來 | 從導覽本身來。N1：導覽專家自己判斷任務，哪個專家挑出的證據最能對上自己的類別文字，就是哪個任務，不存任何舊資料統計量。N2：導覽專家做成共享底座＋每任務低秩增量（LoRA），並可合併成一個不需要任務標識的導覽器。用第二關的數字決定主線，規則寫在 5.3 |
| 5 | 最大的風險 | 四個任務是四個器官，任務辨識本來就容易（pathselect 8/21 的 S1 probe：slide 平均 CONCH 特徵做 4 類 logistic regression，test 0.9821；四任務資料一起訓練的線性 probe，不是 CL 可用的 TP，只當參考上限），所以 CIL 會接近 TIL，審稿人會問。對策：TP 單獨報 |
| 6 | 兩週做到哪 | 第一週完成第一到三關：乾淨 WP、TP 各變體、CIL 十折兩序。第二週做 N1／N2 與結果表。場次建議 ISBI 2027（四頁，10/26 截稿） |

## 1. 老師的構想（整理版）

### 1.1 名詞

| 名詞 | 意思 | 在我們的設定 |
|---|---|---|
| TIL（task-IL） | 測試時給任務標識，只在該任務的類別裡選 | 已知是 BRCA，在 IDC／ILC 二選一。benchmark 裡叫 Masked ACC |
| CIL（class-IL） | 測試時不給任務標識，在所有已見類別裡選 | 學完四個任務後 8 選 1。benchmark 裡叫 ACC；QPMIL-VL 的 0.859（reverse）／0.890（paper order）就是這個 |
| WP | within-task prediction | = TIL 正確率 |
| TP | task-id prediction | 判斷這張 slide 屬於哪個已見任務 |
| 兩者的關係 | 兩階段做法下，CIL 答對 ⇔ TP 對且 WP 對 | 錯誤互相獨立時 CIL ≈ TP × WP |

### 1.2 老師的說法對到什麼

| 老師的說法 | 對應的做法 | 待確認 |
|---|---|---|
| 單任務 0.93 算 TIL | WP 模組 = 每任務一個 NavRouter（導覽器庫） | 0.93 實際不是純 TIL，見第 2 節 |
| 跨任務用 LoRA 或 MoE 選能力 | 每任務一個專家＋gate（參數隔離） | LoRA 加在導覽器，還是 CONCH 文字端 |
| T-Hard：patches 求 mean，和 text embedding 算 cosine | TP 模組，zero-shot，不存資料 | 同學的定義 |
| 不知道 task-ID 也能做到，自然就是 CIL | TP＋WP 組合 | — |
| 0.93 × 0.92 ≈ 0.85，和 QPMIL 差不多 | CIL ≈ TP × WP | QPMIL-VL 在 paper order 是 0.890，兩序都要比 |
| 不做 replay | rehearsal-free；每任務只存專家權重 | 每任務存一個 512 維平均向量（prototype）算不算 replay，請老師定 |
| 前面不要複雜，一關一關來 | 每關只加一個變數，判準先寫死 | — |
| 出成績後加 novelty | 第四關 | 要避開 MergeSlide、COSFormer、TUNA |

## 3. 文獻位置

| 方法 | 做了什麼 | 和老師構想的重疊 | 我們的處理 |
|---|---|---|---|
| Kim et al., NeurIPS 2022 | CIL 可分解成 WP 與 TP | 老師的乘法 | 當理論依據引用；WP、TP、CIL 分開報 |
| MergeSlide, WACV 2026 | TITAN 特徵；每任務只調 slide aggregator，再正交合併；CIL 推論先用 task-level prompt 判任務，再用 class prompt 判類別；不用 replay | = T-Hard | T-Hard 當基線，引用 MergeSlide |

## 4. 設計原則：CL 裡 MoE 的 gate 就是任務辨識

不做 replay 的 MoE，gate 要由「每來一個任務加一塊、不動舊的」東西組成：

| gate 的做法 | 每任務要存什麼 | 新任務來時做什麼 | 會不會忘 | 例子 |
|---|---|---|---|---|
| 文字 key | 不存資料，只有類別或器官名稱 | 把新任務的文字編碼加進去 | 不會；受 CONCH 零樣本能力限制 | T-Hard、MergeSlide |
| 統計量 key | 一個 512 維平均向量（或再加共用 covariance） | 用新任務訓練資料算一次 | 不會；存的是統計量，不是 slide | S-Prompts、FeCAM |
| 專家自評 | 不存額外東西 | 無 | 不會；但各專家分數的尺度要能比 | TUNA（entropy）、N1（證據） |
| 可訓練 gate | gate 權重 | 重新訓練 gate | 不看舊資料就會 | 不採用 |

## 5. 實驗階梯（每關只加一個變數，判準先寫死）

### 5.1 共同設定

| 項目 | 設定 |
|---|---|
| Benchmark | 四任務 TCGA（ESCA、RCC、BRCA、Lung，各 2 類），ConSlide 提出、QPMIL-VL 釋出的 split 與 CONCH 特徵；十折；reverse 與 paper 兩序 |
| 程式基底 | 新 repo `navrouter-cil`，只從 pathselect 複製乾淨元件；不從 navipath 帶任何程式；`tests/test_no_banned_deps.py` 禁用 QPMIL 相關字 |
| 凍結的部分 | CONCH 影像與文字編碼器；類別文字 = `data/class_prompts.json` 經 CONCH text tower 編碼、每類 prompt 取平均再正規化；logit scale 取自 CONCH checkpoint |
| 導覽器 | EvidenceSelector（514→256→1，約 132K 參數），5 epochs、lr 5e-4、top-64 soft aggregation、CE。CE 與 2 維文字摘要都只用**該任務自己的 2 個類別**，因此導覽器和任務順序無關 |
| 選片 | K = 64，每輪 16，共四輪；λ 在 fold 1 的 validation 上從 {0, 0.5, 1.0, 1.5, 2.0} 選一個，之後十折固定 |
| 指標 | ACC（CIL）、Masked ACC（TIL）、TP 正確率、Forgetting、每任務參數量與儲存量 |
| 機器 | 同一台、同一批；每批記錄機型 |

### 5.2 第一關：乾淨的 WP（TIL）

| 項目 | 內容 |
|---|---|
| 問題 | 拿掉 QPMIL-VL 之後，每任務一個導覽器的 TIL 還有多少 |
| 做法 | 1a：重現 8/21 的乾淨重測（答對張數容許 ±1）。1b：乾淨文字頭下重訓導覽器，十折 |
| 對照 | zero-shot 全部 patch 平均、zero-shot top-64、random-64、導覽器一次 top-64、導覽器四輪 |
| 判準 | 導覽器四輪的 Masked ACC 十折平均 ≥ 0.90，比 zero-shot top-64 高 ≥ 0.03，且贏的折數 ≥ 7/10 |

### 5.3 第二關：TP（任務辨識，不訓練）

| 變體 | 做法 | 每任務要存什麼 |
|---|---|---|
| TP-oracle | 真實任務 | — |
| TP-text-class（T-Hard 重建） | slide 所有 patch 平均 → 對所有已見類別文字算 cosine → 最大者所屬任務 | 不存 |
| TP-text-organ | 同上，文字改成器官 prompt | 不存 |
| TP-patch-vote | 每個 patch 投給最相近類別所屬的任務，只算 max 相似度前 10% 的 patch，多數決 | 不存 |
| TP-proto | 每任務訓練 slide 的平均向量當 key，取最近者 | 512 個數 |
| TP-nav（N1 雛形） | 每個已見任務的導覽器各選 64 張 → 平均 → 分數 = 對自己類別文字的最大 cosine − 對其他已見類別的最大 cosine | 不存 |

判讀規則（看數字前寫死）：

| 結果 | 結論 |
|---|---|
| TP-text-class ≥ 0.97 | 任務辨識在這個 benchmark 上沒有空間；N1 降為消融，第四關主做 N2 |
| TP-text-class ≤ 0.95，TP-nav ≥ TP-text-class + 0.03，且 TP-nav ≥ TP-proto − 0.005 | N1 成立 |
| 其他 | N1 列為消融，第四關主做 N2 |

### 5.4 第三關：CIL = TP ∘ WP

| 組合 | 做法 |
|---|---|
| Hard | TP 選出任務 → 該任務導覽器選片 → 在該任務的 2 類裡判 |
| Hard-8 | 同上，最後在所有已見類別裡判 |
| Soft | 各任務權重 π = softmax(TP 分數 / T)，把各專家的類別機率加權 |
| 無 gate 對照 | zero-shot 8 類；E-max |

判準：無儲存 TP＋Hard 的 ACC，兩序都 ≥ QPMIL-VL（0.859／0.890），零 replay。

### 5.5 第四關：專家的形式與新穎性

| 候選 | 做法 | 判準 |
|---|---|---|
| N1 導覽即任務辨識 | 第二關 TP-nav 的主版本固定 | 5.3 的判讀規則 |
| N2 低秩導覽專家 | 第一個任務訓練完整導覽器當底座並凍結；之後每任務只學第一層的 rank-r 增量（r ∈ {1, 2, 4, 8}） | r = 4 的 Masked ACC 與完整每任務導覽器差 ≤ 0.01 |

（後續實際結果：N1 不成立；N2 成立，rank 2 即足夠；之後 router 改為閉式 ridge、expert 縮成 1,033 參數修正頭，見 history 的 NC5–NC8 與 MOE 系列。）

## 10. 給紅隊的四個主張

| # | 主張 | 請打的地方 |
|---|---|---|
| 1 | T-Hard 等於 MergeSlide 的 task-to-class 推論，只是換成 CONCH | 有沒有差別是我們漏看的 |
| 2 | 導覽器的零遺忘是結構造成的，不算貢獻 | 審稿人會不會因此否定整個 CIL 結果 |
| 3 | 四器官 benchmark 上 TP 偏容易 | 需不需要在投稿前加一個同器官的任務序列 |
| 4 | N1（導覽即任務辨識）和 TUNA 的 entropy 選 adapter 不同 | 差別夠不夠當貢獻 |
